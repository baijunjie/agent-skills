# 修改工作流

项目指令文件里 `<!-- setup-agent:workflow:begin -->` 与 `<!-- setup-agent:workflow:end -->` 之间的「工作流」一节
是项目里唯一写工作流的地方：开工前与交付前何时调用什么、按什么顺序、何时跳过。所有修改都只在这对标记之间进行，
标记本身不删不改。指令文件里还没有这对标记时，停下来请用户运行 setup-agent 的 workflow 安装器，生成这一节后再改，
不要自己新建；安装器不生成这一节时（项目里没装 `agent-docs`、`agent-unit-test`、`agent-change-check`），
告诉用户工作流无从登记，不另建。

## 只写调度

- 每一步只写：什么时候做、交给哪个 skill 或执行什么命令、排在哪一步之后、什么情况下跳过。
- 做法细节（怎么审、测试怎么写、文档写什么）归负责它的 skill，不复制进来；要改做法就改那个 skill。
- 「### 本项目」里的条目不得削弱「### 交付前」开头的总规则（如免掉自检、跳过用户确认）。

## 改在哪

- 「### 本项目」小节以外的内容由 setup-agent 的 workflow 安装器按项目里已装的 `agent-docs`、`agent-unit-test`、
  `agent-change-check` 生成，重装时整体重写，不在那里写项目特有的内容。
- 项目特有的步骤、顺序与跳过条件只写进「### 本项目」小节，不另起一节，也不散写到指令文件别处或其它文档。
  每条以上面的步骤名为锚点，不用步骤编号（编号随已装的 skill 变化）：
  - 「在『改动检查』之后：……」「在『开工前』最后：……」——加一步。
  - 「『补单元测试』的跳过条件：……」「『文档更新』改到『改动检查』之前」——改已有步骤的跳过条件或顺序。
  - 锚点所在的步骤或小节当前不在时，先问用户。
- 写第一条时把小节里括号括起的占位行换掉；条目全删光时写回这一行占位：

  ```
  （暂无。项目特有的步骤以上面的步骤名为锚点逐条写在这里，如「在『静态检查』之后：……」「『静态检查』的跳过条件：……」。）
  ```
- 其它 skill 或安装器不得自己往指令文件里写工作流内容；需要登记步骤，就按本 skill 改「### 本项目」小节。

## skill 增删后同步

- 增删的是 `agent-docs`、`agent-unit-test`、`agent-change-check` 之一：停下来，请用户运行 setup-agent 的 workflow
  安装器重建「### 本项目」以外的内容；之后把「### 本项目」里锚定在已删步骤上的条目改掉或删掉。
- 增删的是其它专职 skill：在「### 本项目」里加一条并点名这个 skill，写清它属于开工前还是交付前、排在哪一步之后、
  何时跳过；删掉的就删掉对应条目，其它条目里提到它的地方一并改掉。拿不准它该不该进工作流、放在哪一步时先问用户。
- 只写当前装着的 skill，没装的不留占位。

## 不归这一节的

讲「什么时候调用什么、什么顺序、何时跳过」的归工作流；讲「做事时要遵守什么」的是行为规范，不归这一节——输出风格（如 Concise+）、子代理分派规则都属于后者，不搬进来，改工作流时也不去动它们。

## 改完

告诉用户改了哪几条；指令文件的改动要提交进版本库，下次会话生效。
