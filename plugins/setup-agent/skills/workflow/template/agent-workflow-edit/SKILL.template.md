# 修改工作流

项目指令文件里 `<!-- setup-agent:workflow:begin -->` 与 `<!-- setup-agent:workflow:end -->` 之间的「工作流」一节
是项目里唯一写工作流的地方。

- 只在这对标记之间改，标记本身不删不改。
- 项目里没有任何指令文件带这对标记时不要自己新建：汇报，请用户运行 `setup-agent:workflow` 安装器生成这一节后再改。
- 项目里所有带这对标记的指令文件（如 `CLAUDE.md` 与 `AGENTS.md`）一并改、保持一致；两份互为软链的是同一份，只改它指向的那份实际文件。
  只有部分指令文件带标记的，改带的那些并汇报哪份没有；拿不准哪份生效、或几份现有内容已不一致时，汇报。
- 拿不准某一步该不该进工作流、放在哪一步时，汇报。

## 写什么

- 每一步只写调度：什么时候做、交给哪个 skill 或执行什么命令、排在哪一步之后、什么情况下跳过。
  做法细节归负责它的 skill，要改做法就改那个 skill。
- 讲「做事时要遵守什么」的行为规范（输出风格、子代理分派规则等）不归这一节，不搬进来，也不去动。
- 「本项目」里的条目不得削弱「交付前」开头的总规则（如免掉自检、跳过用户确认）。

## 改在哪

- 「本项目」小节以外的内容由 `setup-agent:workflow` 安装器按项目里已装的 `agent-docs`、`agent-unit-test`、
  `agent-change-check` 生成，重装时整体重写。项目特有的步骤、顺序与跳过条件只写进「本项目」小节。
- 每条以步骤名为锚点，不用步骤编号（编号随已装的 skill 变化），如「在『改动检查』之后：……」
  「『补单元测试』的跳过条件：……」「『文档更新』改到『改动检查』之前」。锚点所在的步骤或小节当前不在时，汇报。
- 写第一条时换掉小节里括号括起的占位行；条目全删光时写回这一行：

  ```
  （暂无。项目特有的步骤以上面的步骤名为锚点逐条写在这里，如「在『静态检查』之后：……」「『静态检查』的跳过条件：……」。）
  ```
- 其它 skill 或安装器需要登记步骤，也按本 skill 改「本项目」小节，不自己往指令文件里写工作流内容。

## skill 增删后

- 增删的是 `agent-docs`、`agent-unit-test`、`agent-change-check` 之一：汇报，请用户重新运行 `setup-agent:workflow`
  安装器重建「本项目」以外的内容；重建后锚定在已删步骤上的「本项目」条目逐条列给用户，由用户决定改锚点还是删掉。
- 增删的是其它影响开工前 / 交付前流程的专职 skill：在「本项目」里加一条点名它，写清属于开工前还是交付前、排在哪一步之后、何时跳过；
  删掉的，连同其它条目里提到它的地方一并去掉。只写当前装着的 skill，不留占位。

## 改完

告知用户改了哪几条，并提醒用户：指令文件的改动要提交进版本库才随仓库生效，下次会话生效。
