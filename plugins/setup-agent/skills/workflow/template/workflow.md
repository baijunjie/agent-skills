# 工作流

本节只定开工前与交付前何时调用什么、按什么顺序、何时跳过；每一步怎么做以对应的 skill 为准。

<!-- if-installed: agent-docs -->
## 开工前

先按 `agent-docs` skill 了解项目上下文。

<!-- end-if -->
## 交付前

自检针对的是一次**完整交付**，不是每一次编辑。本次改动全部写完后：

- 有需要用户确认的内容（待拍板的决定、要问的问题、用户说过要先过目的改动、影响较大的自行决定），
  就先汇报、等用户反馈，按反馈改完再重新判断。
- 没有就直接自检收尾。用户要求推送、发 PR 或合并时，也直接自检。

阶段性提交不算交付。用户在交付前明确要求「现在审一下」「先更新文档」时照做。

交付时按以下顺序逐项自检：

<!-- if-installed: agent-unit-test -->
1. **补单元测试**：按 `agent-unit-test` skill 为本次改动补测试。
<!-- end-if -->
2. **静态检查**：执行项目约定的质量检查命令（格式化、类型检查、Lint 等），确认无报错。项目没约定就跳过。
<!-- if-installed: agent-change-check -->
3. **改动检查**：按 `agent-change-check` skill 审本次改动；按意见改了代码就先重跑静态检查与受影响的测试，再复审；
   审查通过、或剩余意见已交给用户定后，才进入下一步。
<!-- end-if -->
<!-- if-installed: agent-docs -->
4. **文档更新**：本次改动要更新给后来者看的文档时，按 `agent-docs` skill 更新；与文档对齐时改了代码，
   重跑静态检查与受影响的测试。
<!-- end-if -->
