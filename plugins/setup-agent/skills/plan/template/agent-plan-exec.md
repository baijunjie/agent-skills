# 按开发计划文档执行开发

「汇报」指停下，写清要定的事（有哪些选项）或缺的信息，连同已查明的情况一起报出，由收到汇报的一方（用户，或由派发者转给用户）决定后再继续，不要自行决定。

## 选定开发任务

开发计划文档目录默认 `docs/plans/`，项目已有自己的约定时按项目的。

用户指明了做哪份开发计划文档就做哪份。没指明时，自己到开发计划文档目录里挑一个当前最适合开工的里程碑。

挑选判据：

- 优先接着已开工的主题往下做——有里程碑已勾了一部分，或前序里程碑已收尾的主题
- 同一主题内按编号取第一个还没收尾的里程碑；前序里程碑还没收尾的不能跳过去做后面的
- 多个主题都可开工时，取依赖最少的那个

选定与挑不出时：

- 选定后先说明做的是哪个里程碑再开工
- 目录不存在或是空的：直接说没有可做的开发计划
- 候选之间取舍不清（优先级相当、互相有依赖）：汇报，列出候选让用户拍板，不要自己硬挑

## 如何读开发计划文档

- **主题目录**：开发计划文档目录下的 `YYYYMMDD-{开发简述}/`，一个开发主题一个目录
- **总览文档**：主题目录下的 `README.md`——问题描述、方案概述、关键设计决策；
  拆成多个里程碑时这里还有里程碑清单。清单里写成 `NN 已收尾` 的条目，对应文档已删掉；保留着的留账里程碑同样算已收尾（见下面「留账里程碑文档」）
- **里程碑文档**：按编号排序的文件，一份对应一个能独立测试、能独立合并的里程碑，
  开头点明目标与完成判据。编号即依赖顺序，按顺序做
- **只有 `README.md` 的目录**：说明这个主题只有一个里程碑，总览与里程碑内容都在这一份里，
  按它开发即可，不要另建编号文档
- **留账里程碑文档**：「目标 / 完成判据」之后紧接着有「落地状态」节的里程碑文档，表示已收尾、因留账仍保留；挑选时视为已收尾，
  不按未勾条目判断。开工前先读本里程碑依赖的那几份的「落地状态」节——那里写着实际做成了什么、
  留下了哪些过渡层。**过渡层都标了 TODO，不要当成遗漏顺手删掉**，各自写明了由哪个里程碑删
- **checkbox 条目**：完成一个就立即勾上，严禁攒到最后批量勾

## 如何了解项目上下文

- 项目有自己的文档规范就先读它，文档目录与本项目额外的规则以它为准
- 否则从总索引（默认 `docs/README.md`）入手，按项目地图定位要动的模块，
  再读对应的产品文档确认现有行为

## 里程碑收尾

收尾前先按开头的「完成判据」逐条验证，验证不过不算做完，验不了的部分如实说明。

| 未完成条目 | 能否收尾 |
|---|---|
| 全部勾完 | 可以 |
| 有未完成，但已有明确去向（挂到后面某个里程碑、或等外部条件） | 可以，就地写明去向 |
| 有未完成，且无明确去向 | 不可以，先汇报去向（单独排期 / 本次做完 / 放弃），收到决定后再处理 |

收尾分三步，**前一步没做完不许做下一步**。

### 1. 固化

把本里程碑做完的东西里有长期价值的部分整理进产品文档与项目地图。

- 判据是**读代码本身得不到、但接手时必须知道**；纯内部实现细节、换实现而外部行为不变的改动不写
- 项目有自己的文档规范的按它的规定做
- 没有的自己整理，落笔前必须先完整读一遍要改的那几份文档
- **刻意留下的过渡层不进产品文档**，除非它造成了用户看得见的行为差异——那就如实写现状并标明是过渡态，
  但不写计划、不带里程碑编号

### 2. 写落地状态

**判据是本里程碑有没有东西要交给后面的里程碑**：

| 类型 | 判据 | 这一步 |
|---|---|---|
| **自足里程碑** | 没有东西要交给后面的里程碑 | 跳过 |
| **留账里程碑** | 留下了后面要拆的过渡层、要接的接口，或要后面了结的口径 | 写「落地状态」 |

在本里程碑文档里紧接开头的「目标 / 完成判据」之后、正文之前加一节「落地状态」，写：

- 最终形态与原计划的差异
- **刻意留下的过渡层**，逐条写明由哪个里程碑删掉；代码里同步标 `TODO`
- 交给后续里程碑的账：眼下没有调用方的接口、尚未统一的口径、待补测的项
- 验证方式，以及**没验证的部分**

正文里作废的计划不必清理。

### 3. 删除

删除放在上面按完成判据的验证通过、且项目要求的审查（若有）也通过之后。

| 类型 | 本里程碑做完时怎么做 |
|---|---|
| **自足里程碑** | 确认已固化，删掉这份文档，`README.md` 总览里程碑清单里对应的条目改成一行 `NN 已收尾`（`NN` 为它的编号） |
| **留账里程碑** | **不删**，等它交出去的账全部了结才能删——账还没人接就删掉，接手的人只能从代码反推 |

本里程碑了结了某份留账里程碑的最后一笔账时，把那份一并删掉，`README.md` 总览里对应的条目同样改成 `NN 已收尾`。
留着这一行，是为了让后来追加的里程碑不复用这个编号——
留账里程碑的「落地状态」和代码里的 `TODO` 按编号写着由哪个里程碑删。
主题目录里的里程碑文档全部删掉后，`README.md` 总览随之删掉，再删主题目录；整个主题删掉时才全部**不留痕**。

只有 `README.md` 的主题按自足里程碑处理：固化后直接删掉 `README.md` 和主题目录。

开发计划文档目录因此空了的一并删掉。
