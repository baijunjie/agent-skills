# 编写开发计划文档

「汇报」指停下，写清要定的事（有哪些选项）或缺的信息，连同已查明的情况一起报出，由收到汇报的一方（用户，或由派发者转给用户）决定后再继续，不要自行决定。

**简洁整理**成开发计划文档，只整理以下输入范围内的内容，不添加额外信息、不自行添加推测的方案；输入很长时也不丢设计决策与理由，只删去叙述性内容：

- 本次讨论确定的方案
- 用户给出的完整需求描述
- 开发中发现并已向用户说明的追加功能（没向用户说明过的，先汇报，不写）

追加功能是指当前任务进行中发现、可独立开发、不属于本次任务的功能。写计划不等于动手实现：
写完不要动手实现，追加功能不进入本次改动。

输入里没定下来的设计点不要补：不影响里程碑拆分与完成判据的，写在 `README.md` 总览末尾的「待定」一节；会让某个里程碑说不清目标或完成判据的，汇报，已经能确定的部分可以先写，受影响的里程碑先不写。

开发计划文档目录默认 `docs/plans/`，项目已有自己的约定时按项目的。

开发计划文档目录里只放**尚未做完**的内容：方案设计、开发计划、待办清单。

本 skill 只写新的主题；往已有主题追加或调整里程碑不在它的范围内。写完只落盘，不自行提交，把写在哪个目录告诉用户。

## 目录与拆分

- 一个开发主题一个目录 `YYYYMMDD-{开发简述}`，简述用仓库既有文档的语言。
  不要把文档直接放在开发计划文档目录根下。
  日期是目录的创建日期，不代表开发周期——跨度大、分多次做完的主题同样只有一个目录
- **追加功能**必须另建主题目录，不并进当前正在做的主题
- 一份里程碑文档对应一个**能独立测试、能独立合并**的里程碑：这一份做完，代码应当可以自行验证并合入，
  不必等后续文档一起才跑得通。验证不一定是跑业务行为，迁移能执行、类型检查通过、单元测试通过都算；实在没有任何可验证的，就并进相邻的一份（优先下一份，没有再并进上一份）
- 拆多细由你裁量：一个里程碑可以横跨数据、逻辑、接口、界面多个层次，也可以只动一个文件。
  不要为凑数硬拆，也不要把彼此独立的两块塞进一份
- 按依赖方向排序，被依赖的里程碑排在前面（通常是数据结构 → 核心逻辑 → 对外接口 → 调用方）
- **只有一个里程碑时，目录下就只放 `README.md`**，总览与该里程碑的内容合在这一份里写：先是总览，再是里程碑的目标与完成判据块、技术设计、实现方案、开发者提示
- 拆成两份及以上时，`README.md` 退回纯总览，里程碑内容放进各自的编号文档，
  命名 `[编号]-[开发简述].md`（如 `01-订单状态存储与迁移.md`），编号即开发顺序。

## 写什么

**`README.md` 总览**：问题描述、方案概述、关键设计决策及其理由。拆成多个里程碑时在这里维护里程碑清单。

**里程碑文档**（单份时即 `README.md`）：

- 开头点明本里程碑的目标与完成判据，格式为：

  ```
  > 目标: <这一份要做成什么样>
  > 完成判据: <怎么算做完、怎么验证>
  ```

- **技术设计**：输入范围内的接口签名、数据结构、核心方法定义
- **实现方案**：输入范围内的重构策略、方法分解、调用流程框架
- 技术设计与实现方案里的每一项写成 checkbox 条目，粒度取可独立验证的最小一项；写作时一律 `- [ ]`，勾选与计划文档的清理由执行阶段负责；输入里没有的节省略，目标与完成判据块、开发者提示不写成 checkbox
- 末尾给开发者提示，这是唯一需要查看项目现状的部分，其余仍以输入为限，只到「项目里已经有什么、该复用哪一块」的粒度（无内容的项省略）：
  - **可复用能力**：项目里已有、本里程碑应当直接复用的机制或模块（鉴权、缓存、错误处理、公共组件、
    工具函数等）。指到能力与所属模块即可，可以写模块名，不写文件路径；不确定项目里有没有就不写，别猜
  - **开发要点**：需要遵守的开发规范、与现有系统的集成方式，强调已实现的全局功能，防止重复实现
  - **参考文档**：相关技术文档、规范文档的路径（文档路径可以写）

## 不写什么

- **完整实现代码** —— 绝对不写函数体内部逻辑。允许的示例只到方法间调用关系与执行流程，
  且被调用的方法都是输入范围内确定的；含具体业务逻辑、算法实现、第三方库调用的示例一律不写。
  可以写「校验通过后调用 A，再调用 B」；不可以写「状态为 X 时走分支一、否则走分支二」这类实现层面的分支伪代码。
  输入里的业务规则、约束（如「已支付的订单不可取消」）是设计决策，用自然语言原样写进设计里，不受此限
- **代码落点** —— 不列要改哪些文件、不指定代码放进哪个路径，那是实现阶段由开发者调查确定的
- **编码实施指导** —— 不写具体的编码步骤
- **重复描述** —— 各文档之间不出现重复内容；后面的文档依赖前面的就简洁引用，每份只聚焦自己那个里程碑
- 输入里提到过被放弃的实现方案时，在它所属的里程碑或主题文档里随文稍作说明即可，不另立清单

## 与别处的关系

- **开发计划文档不进项目文档的总索引**，新增或删掉主题目录都不必改总索引
- **它是临时文档，不是长期资产**
- **主题目录之外的任何地方都不许引用它**（同一主题目录内的文档互相引用不受此限） —— 引用是单向的：开发计划文档可以引用任何别的东西，反过来不行，代码注释、提交说明、PR 描述里也不引用。
  别处需要它里面的内容，直接写进那份文档
