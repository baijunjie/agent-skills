# 按开发计划文档执行开发

「汇报」指停下，写清要定的事（有哪些选项）、缺的信息或需要用户协助的事，连同已查明的情况一起报出，由收到汇报的一方（用户，或由派发者转给用户）决定后再继续。

下面只定原则和不能越过的边界，其余细节自行判断；**拿不准就汇报**。

## 计划文档的结构

- 开发计划文档目录默认 `docs/plans/`，项目已有自己的约定时按项目的。项目有自己的文档规范时先读它，额外规则以它为准
- 一个主题一个目录 `YYYYMMDD-{开发简述}/`。`README.md` 是总览：问题描述、方案概述、关键设计决策；拆成多个里程碑时还有里程碑清单
- 里程碑文档命名 `[编号]-[开发简述].md`，编号即开发顺序（`02` < `02a` < `03`）。只有 `README.md` 的主题只有一个里程碑，内容合在这一份里；要新增里程碑时，先把里程碑内容拆成 `01-…`，`README.md` 只留总览并加上清单
- 里程碑开头的「目标 / 完成判据」块、checkbox 与「交接」节所涵盖的内容，就是它的**范围**
- checkbox 勾上表示已实现且已验证，做完一项就勾
- 「交接」节：前面的里程碑移交给本里程碑的事（过渡层、要接的接口、待统一的约定等），都是本里程碑的任务。其中标「阻断：原因」的是**阻断项**：条件具备前整个里程碑不开始做
- 「中途交接」节：上次没做完时留下的上下文。接手先读，恢复后有用的并入正文，其余删掉
- 收尾指清账、固化、删除三步，做完即**已关闭**

## 原则

1. **一次一个里程碑。** 用户指明了就做指明的；没指明时自己挑当前最适合做的，不按目录名日期判断优先级，选不出来就汇报。用户要求连做时，前一个关闭了才开始下一个，关闭不了就停下汇报。
2. **关闭就是不留尾巴。** 收尾时先按完成判据验证，再让剩下的每一项都有去向：

   | 剩下的 | 去向 |
   |---|---|
   | 本里程碑范围内、还没做完的 | 现在做完；做不了就不收尾，走中途交接 |
   | 属于本主题后面某个里程碑的（含过渡层的删除） | 写进那个里程碑的「交接」节；没有合适的就新建或插入一个 |
   | 实现已完成、只差验证，且现在验不了的（范围内的也算，这样移交不算缩减范围） | 后面的里程碑依赖它的结果，就作为阻断项写进第一个依赖它的里程碑；不依赖的，汇入最终确认里程碑（没有就新建，排在最后） |

3. **计划目录只放没做完的东西。** 关闭时把读代码得不到、接手又必须知道的内容整理进项目文档（产品文档、项目地图等；项目有文档规范的按它的分工做，如派对应的写作子代理），再删掉里程碑文档。主题里的里程碑全部关闭后，总览里有长期价值的内容一并整理，删掉整个主题目录。
4. **里程碑动手后没关闭就要交还控制时，先留中途交接。** 本次会话要结束、或答复不会在本次会话内到来时都算；当场能等到答复的，或还没动手就停下的，只汇报。中途交接写清做到哪、卡在哪、要什么条件才能继续、已查明的情况与设计取舍、没验证的部分，让下一个人读到就能接着做；已完成部分里读代码得不到的内容照样写进项目文档，里程碑文档里已勾的项保留。
5. **改目标、完成判据、关键设计要汇报，不论该改的是计划还是代码。** 为达成现有目标补漏掉的条目、按代码现状修正计划里的非关键设计、按上表移交，可以直接做。

## 边界

- 前序里程碑未关闭，不跳过去做后面的；用户指明的也一样，汇报
- 最终确认里程碑（`NN-最终确认.md`）只收现在验证不了、又不阻断后续的事，排在主题最后，是终点：其中的项必须做完，不再往后留；确认出缺陷就在它里面修
- 已关闭的里程碑在 `README.md` 清单里改成一行纯文本 `NN 开发简述（已关闭）`，主题目录删除前这一行不删；新里程碑不复用出现过的编号，插在中间用字母后缀
- 已关闭的里程碑只在清单这一行留痕，「交接」节、项目文档、代码注释都不提它
- 只在本主题内移交；属于别的主题、或不属于任何主题的发现，汇报
- 不自行缩减范围，不自行放弃任何一项
- 刻意留下的过渡层在代码里标 `TODO`，写明由哪个主题的哪个里程碑删，转交给别的里程碑时同步改；不归本里程碑的不要顺手删
- 过渡层不进项目文档；造成了用户看得见的行为差异的，如实写现状并标明是过渡态，不写计划、不带编号
