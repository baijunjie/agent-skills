## 分派子代理

**判据：要吃掉大量上下文、又不是改完这一次就结束的任务——探索、排查、调研、批量搜改、反复试——
尽量派子代理去做，自己只收结论。** 小修改亲自动手，交代给子代理的成本比改掉它还高。
另外，需要一个干净视角时也派出去：审自己刚写的代码、写文档，你手上的上下文带着偏见。

**怎么交代**：一次只交代一件事、说清完成判据；背景给全（你没写进去的前提它一概不知道）；
让它报结论、不要复述过程；不要让多个子代理同时改同一处。

**选谁执行**：有专职子代理负责的交给它；没有的按任务难度选，不要一律用最强的。

| agent | 用途 |
|---|---|
| `mechanical` | 批量搜索、代码定位、批量替换、格式化、简单文本与数据处理 |
| `implement` | 编写具体逻辑代码、实现已定方案、目标明确的重构与修 Bug。默认的性价比选择 |
| `investigate` | 跨模块疑难排查、根因定位、大范围重构 |
| `architect` | 架构设计、跨模块改造方案、技术选型。只在确实需要最强推理能力时用 |
