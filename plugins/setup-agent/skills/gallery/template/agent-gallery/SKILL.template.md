# UI 状态 gallery

下面只定原则和不能越过的边界，其余细节自行判断；拿不准就汇报：停下，报清要定的事与已查明的情况，等对方决定后再继续。

gallery 是只在开发时用的场景集合：每个场景用 mock 数据摆出一个 UI 状态，不依赖真实后端，供人确认、供快速检查逐个遍历。

## 本项目约定

本节由安装器按项目现状与用户的选择填写，重装时按项目现状重新核对，确定不了的沿用；有多个 UI 包时表里各填一行，表下各项各包不同时分别写明。

| 范围 | gallery 方案 | 场景放在哪 | 打开 gallery | 场景直达入口 | 快速检查（全量） | 快速检查（指定场景） |
|---|---|---|---|---|---|---|
| <UI 包的路径；只有一个写「整个项目」> | <方案名（项目已有 → 用户选定）；自建的写「自建」与入口文件> | <`gallery-writer` 维护的场景的位置与命名；已有场景另有用途、不归它增删的，写明哪些不归它管> | <启动命令，以及怎么避开别的工作副本、启动后从哪读出实际地址> | <打开一个场景的方式（URL、deep link、启动参数等），含主题、语言、尺寸等查看条件的写法> | <检查全部场景的命令> | <只检查指定场景的命令，用于修场景时反复验证；方案不支持写「无」> |

- UI 检查项：<快速检查对每个场景查什么、在哪些查看条件下查，每项注明工具（第三方的名字或「自建」），如「渲染冒烟（就绪、无失败信号、无未捕获错误）：Playwright；en、zh-Hans；亮色」；另设命令、不进快速检查的检查连同命令与何时跑一起写，没有写「无」；安装时用户同意记明的缺项也写在这里>
- 应用预览：<从当前工作副本启动应用本身的命令、怎么避开别的工作副本、访问时需要的登录或配置；应用离不开真实后端、只能看 gallery 的写「只用 gallery」>
- 预览临时位置：<被版本库忽略、按工作副本隔离的目录：只为预览加的临时场景放在哪（gallery 要能加载它）、本次预览启动的服务记在哪>

## 改 gallery

1. **正式场景、mock 与 gallery 机制的写入都派 `gallery-writer` 子代理，你不写**：场景怎么摆、扩哪个删哪个由它判断。「预览临时位置」不归它，见「预览给用户确认」。
2. **同一时刻只派一个，每次交代全部待摆的状态**：它要在全部场景之间判断该扩哪个、删哪个，同时派几个会各加各的。它看不见你们的对话：交代新增或改变的 UI 状态、每个状态给人确认的是什么、用户定下的取舍。之后修检查失败、改了应用代码、用户提了修改意见，照样再派；本工作副本正在跑预览的，把地址一并交代。
3. 按它的报告处理：报「摆不出来」、要改应用代码才能摆的，你判断改不改，改动大就交给用户定；它定不了的取舍交给用户定；它报地址变了或失效的场景，已经发给用户的入口重新给；它报约定里的命令或检查项要跟着改的，按它更新「本项目约定」。
4. 没有子代理机制时，自己按装进项目的 `gallery-writer` 子代理定义里的标准写。

## 快速检查

- 本次改动涉及 UI、mock 或 mock 依赖的接口契约与类型时，交付前跑**全量**快速检查，全部场景都要通过：共享组件、样式、mock 的改动会波及没改到的场景，只跑改到的查不出来。
- 失败先判原因：本次改动弄坏的，改代码；场景或 mock 跟不上当前 UI 或契约的，派 `gallery-writer` 修，失败的场景不归它管的交给用户定；在开发分支的基线上同样失败、与本次改动无关的，约定里已记为遗留失败的照记录处理、不再问，其余交给用户定，用户决定先不管的，在最终回复里写明是遗留失败、不算通过。不靠删场景、跳过或放宽检查让它通过。
- 通过只说明场景跑得起来，不说明它摆的是最新的 UI：外观与交互要确认的，在浏览器、模拟器或真机里实际看。
- 在最终回复里写清跑了什么、结果如何。

## 预览给用户确认

本次改动涉及 UI、要交给用户确认时：

1. **从开发分支启动预览**：在本次任务的分支或 worktree 里启动 gallery，需要时连同应用预览，按约定避开别的工作副本；不借用别的工作副本里在跑的服务，那里看不到本分支的改动。启动的服务、装上模拟器或设备的构建记进「预览临时位置」；记录里已有的还在跑、显示的是本分支的，直接复用，已经不在的删掉记录。
2. **给直达入口**：汇报里给每个要确认的界面一个直达入口，按约定的「场景直达入口」写、带上查看条件，用启动后的实际地址；先自己打开，确认显示的是本分支的改动，再附上必要的访问说明。
3. **等待确认期间保持运行**：用户提修改意见就改，改完刷新预览，入口变了重新给。
4. 给不出可用的预览就明说卡在哪，不把 UI 改动当作可以确认的交出去。

只为给用户看而临时加、不打算长期留进 gallery 的场景或 mock，你自己写进「预览临时位置」，不混进正式场景；有临时场景的，请用户确认时顺带问要不要留下；要留下的，按 UI 状态交代给 `gallery-writer` 摆进正式场景，再删掉临时那份。

## 收尾清理

用户确认没问题、或同意把分支交出去（合并、推送提 PR 等）后，在交出去之前；工作副本要被删掉的，也在删之前：

- 停掉本工作副本「预览临时位置」里记着的服务，卸掉记着的预览构建；记录之外的服务与构建不碰。
- 用户要留下的临时场景先转成正式场景，再删掉本工作副本「预览临时位置」里的临时场景、mock 与记录；那里之外的文件不删。
- 告知用户预览已停、清掉了什么。

## 找不到约定时

「本项目约定」的表还没填（只剩 `<…>`），或填的命令本身已失效（命令、脚本或路径已不存在，在开发分支的基线上同样跑不起来）：停下来，请用户运行 `setup-agent:gallery` 安装器重新确定本项目约定。本次改动弄得跑不起来的，按快速检查失败处理。
