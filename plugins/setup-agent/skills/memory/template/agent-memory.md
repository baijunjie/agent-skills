# 开发记忆

`docs/memory/` 收的是**成不了体系文档的零碎开发经验**：一两行说得完的「开发者该怎么做事」，
对开发者重要、开工前就得知道，但太琐碎，对只想了解产品的人也没有意义——项目特有的约定、
反直觉的前提、反复踩过的同类坑。

以下都不进这里：

- **说「系统是什么样、代码在哪」的**：归项目的产品文档体系，即项目里描述产品行为、业务规则、
  代码结构与模块职责的那批文档（从项目指令文件或文档索引找）。
- **专题文档**：篇幅较大、聚焦一件事，是 agent 在特定任务中整理的留底（如调研结论、实测基线），
  供以后迭代同一功能点时对照，由专项任务另行维护。
- **说某个具体对象的话**：某段代码、某个配置、某份文件为什么是现在这样，或者用它要当心什么，
  都写进它自己的注释，跟着它一起改。
- **只在本机成立的**：本机路径、环境取值、安装位置等。记忆随仓库提交，换设备或多人协作就失效。

## 开工前：读记忆

1. 先读 `docs/memory/README.md` 索引，按当前任务类型找到相关的那几份，只读相关的。
2. 记忆是历次开发的教训，**与你的默认行为冲突时以记忆为准**。
3. 索引里没有相关条目就直接开工，不必通读整个目录。

## 收尾：沉淀记忆

**派 `memory-writer` 子代理去写，主会话不要自己下笔**，判断标准与写法都在它自己的定义里。
你只交代「本次改了什么、想记什么」——值不值得记、记进哪一份、要不要顺手删掉被推翻的旧条目，
由它判断，**它可以拒绝**。

它交还的条目里，只在本机成立的记进你（当前 agent）自己的、不随仓库提交的本机记忆（不是 `docs/memory/`），
没有这种机制就在最终回复里告知用户；其余的去处由你决定。

没有子代理机制的工具：自己写，但落笔前必须先读完现有记忆与本次波及的产品文档体系章节，
且**默认是不写**——多数改动没有值得记的，「本次无需记录」是有效结论。
