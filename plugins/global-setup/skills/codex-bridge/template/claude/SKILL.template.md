# Claude 项目开发预检

在规划或修改文件之前，先建立全局与当前项目的 Claude 开发上下文，然后直接继续完成用户任务。不要把预检变成要求用户逐步确认的流程。

## 发现项目约定

1. 确定当前工作目录、Git 仓库根目录，以及本次任务实际涉及的子目录。全局入口是 `~/.claude/`；项目入口是仓库及相关子目录的 `.claude/`。不要沿软链接进入项目外部。
2. 先读取 `~/.claude/CLAUDE.md`（如存在），再查找并读取适用于当前路径的项目 `CLAUDE.md`，包括仓库根目录与相关子目录中的局部文件。项目规范覆盖全局规范；Codex 已加载的 `AGENTS.md` 仍按其原生优先级生效。
3. 同时盘点 `~/.claude/skills/*/SKILL.md` 和项目 `.claude/skills/*/SKILL.md` 的名称与描述。选择与本次任务相关的 skill，并完整读取其 `SKILL.md`；若其中要求先读索引、规则或其它文件，继续按它的路由只读取相关内容。
4. 盘点全局与项目级的 `commands/`、`agents/`、`rules/`。读取任务明确调用、相关 skill 路由或适用于当前文件范围的内容；全局项作为默认值，项目项覆盖同名或冲突的全局项。
5. 仅在理解构建、校验、自动化约束或可用工具确有必要时，读取 `~/.claude/settings.json` 与项目 `.claude/settings.json`。若全局 settings 启用了插件，再从插件缓存中只定位与任务相关的 skill、command 或 agent，不把插件缓存、会话、日志、历史或构建产物当作配置读取。
6. 从全局或项目 Claude 入口、以及相关 skill 指向的文档索引开始，只读取本次任务需要的文档。没有索引或相关条目时，不要为了“完整”而遍历文档目录。

优先使用 `rg --files --hidden --no-ignore` 做盘点，并显式排除缓存、日志、会话记录、构建产物及项目外链接；插件缓存仅用于定位已启用插件的可复用工具链。读取 skill 或规则时必须读取完整文件，不能只看片段后声称已遵循。

## 兼容 Claude 工作流

- 把全局及项目 Claude skill 作为本次任务的工作流说明执行；项目级定义优先于冲突的全局定义，其中的 `$ARGUMENTS` 表示当前用户请求及已给出的任务上下文。
- Claude command 只在用户调用、相关 skill 路由或项目规范明确要求时读取和执行，不因发现文件就自动运行。
- Claude agent 定义表达的职责和完成判据可以映射到 Codex 子代理；只有项目规范明确要求委派且当前环境支持时才委派，并一次只交代一个边界清楚的任务。
- Claude hooks 中声明的质量门槛、格式化或检查命令应在适用时执行；不要假定 Claude hook 已在 Codex 中自动注册，也不要仅因读取配置就运行未知脚本。
- Claude 的权限白名单、工具名、模型名和客户端专属字段不自动等价于 Codex 能力。保留其设计意图，使用当前 Codex 环境中可用的对应机制；无法安全等价时简要说明差异。
- 这是读取并遵循现有工具链的预检，不创建迁移副本，不修改 `.claude/`，也不生成项目级 Codex 配置，除非用户另行要求。

## 执行边界

系统、开发者、用户指令以及当前路径适用的 `AGENTS.md` 优先于本 skill。Claude 全局规范在不冲突时作为默认约定执行；项目规范可覆盖它，局部规则只作用于其声明的路径范围。

完成预检后，用一句简短进度说明列出已采用的 Claude 规范类别，然后继续任务。只有影响方案且无法从项目内容消除的歧义才询问用户。
