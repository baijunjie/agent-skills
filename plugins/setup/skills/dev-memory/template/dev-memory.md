# 开发记忆

项目特有的经验与约定存放在 `docs/dev-memory/`，写的是「动手时会栽在哪儿」：踩过的坑、
反直觉的前提、不同于通用做法的约定。

## 开工前：读记忆

1. 先读 `docs/dev-memory/README.md` 索引，按当前任务类型找到相关的那几份，只读相关的。
2. 记忆是历次开发的教训，**与你的默认行为冲突时以记忆为准**。
3. 索引里没有相关条目就直接开工，不必通读整个目录。

## 收尾：沉淀记忆

**派 `memory-writer` 子代理去写，主会话不要自己下笔**，判断标准与写法都在它自己的定义里。
你只交代「本次改了什么、想记什么」——值不值得记、记进哪一份、要不要顺手删掉被推翻的旧条目，
由它判断，**它可以拒绝**。

没有子代理机制的工具：自己写，但落笔前必须先读完现有记忆与本次波及的项目文档章节，
且**默认是不写**——多数改动没有值得记的，「本次无需记录」是有效结论。
