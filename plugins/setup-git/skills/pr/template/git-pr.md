# 提交 PR

## 目标分支

- 调用时指定了分支就提到那个分支，只对本次生效。
- 没指定就提到 `{{PR_BASE}}`。
- 动手前先 `git fetch` 目标分支，后面的比较与压平都以远端的最新状态为准。

## 步骤

1. **准备分支**：有未提交的改动时先问用户是否纳入本次 PR。当前就在目标分支上时：
   - 先 `git switch -c` 另建新分支承载本地提交（按变更类型取 `feat/`、`fix/` 等前缀）；
   - 再用 `git branch -f` 把本地目标分支退回远端位置，否则这些提交会残留在上面。
     只有它比远端多出的提交全属于本次 PR 时才退回，混有别的提交就先问用户。
2. **压平**：已是单个提交就跳过。多个提交一律在原基点上压：
   `git reset --soft $(git merge-base HEAD origin/<目标分支>)` 后重新提交。
   不要 reset 到目标分支的最新提交——基点换了而内容没合，会悄悄撤销目标分支上的改动。
   确实包含多个互不依赖的变更时才保留多个提交。提交信息格式与语言跟随仓库历史。
3. **推送**：分支已推送过而压平改写了历史时，要 `--force-with-lease`；只有自己独用的分支才能强推，推之前先问用户。
4. **提交 PR**：用远端所在平台的 CLI 创建（GitHub 用 `gh`）。仓库有 PR 模板时按模板填写正文。
   不主动 rebase；PR 与目标分支冲突时告诉用户，要解冲突就把双方的改动合起来，一律取自己这一侧等于撤销目标分支上的改动。
5. **清理本地**：确认 PR 已创建、分支已推到远端后立即清理，这是提交 PR 的一部分，不必再问——
   - 分支在某个 worktree 里：先离开该 worktree 目录，再 `git worktree remove`；
   - 主工作副本停在该分支上：切回目标分支（本地没有就从远端建跟踪分支）；
   - 最后 `git branch -D` 删除本地分支。

   worktree 里有未提交或未跟踪的文件、目标分支被别的 worktree 占用而切不回去时，停下来问用户，不要加 `--force`。

操作被仓库的 git hook 拦下时照提示处理，不要绕过。
