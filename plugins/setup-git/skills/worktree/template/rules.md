# 开发流程：Git Worktree

- 目标分支是创建 worktree 时当前工作副本检出的分支（嵌套时是父分支）；下文的「主工作副本」指检出目标分支的那个工作副本。
- 产生代码变更的任务，一律在独立的 git worktree + 独立分支上完成，编辑、构建、测试、质量检查都在里面进行；主工作副本保持干净，便于随时对照目标分支。只读排查、答疑这类不产生改动的操作除外。只为验证而临时注入代码时，可另开不建分支的临时 worktree（`git worktree add --detach`），里面的改动不提交、验完即删。
- 目标分支不一定是主分支；开发分支从它的最新提交拉出，最终也合并回它。创建分支时必须记下它的目标分支与切出点，漏记了换个会话就查不到该合并回哪，也核对不出合并有没有撤销目标分支上已有的改动。
- 创建 worktree、对齐远程的目标分支、压平提交、rebase、合并回目标分支、推送目标分支，以及撤销目标分支上已有的提交或改动，都按 `git-worktree` skill 的步骤做。不要加 `--no-verify`、设跳过用的环境变量或改 hook 配置去绕过仓库的检查。
- 项目改走 PR 合并时，以 PR 流程为准，不在本地 merge，PR 的目标分支用该分支记录的 `worktreeTarget`。
