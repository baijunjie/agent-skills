# 界面文案规范

每种语言都写短、写顺、一次读懂。句子说完，按钮用短词。不写俚语，不写没说完的残句。

要说的事实和篇幅跟源语言对齐，句式用这种语言自己的界面习惯，**不把源语言的句架逐词搬过去**。
审查时逐条通读整句，按这种语言的那一档判断；只扫关键词会漏掉用错档的句子，也会把该留的缩约扫掉。

项目自己的文案规范、术语表与本文冲突时，以项目的为准。本文标「默认」的是常见 C 端 App 的取值，项目另有定位（B2B、金融等）时可改。

## 各语言语体

模型写出的中文口语又拧又长，所以简体用书面短句；这是简体的办法，不是所有语言的语体。
别的语言再往公文、敬称推一档，常常更长，跟「写短」相反。

| 语言 | 默认用这一档 | 不用 |
|---|---|---|
| zh-Hans | 书面短句 | 口语拧句、日式语序、日文中点「・」 |
| zh-Hant | 短句，默认台湾用语，人称用「你」；概念口径与简体同一套，用词换成繁体界面的词 | 简体公文词、简体用词照搬 |
| en | 带常见缩约的完整句 | 俚语、残句 |
| ja | 句子ですます，按钮短名（キャンセル、後で） | 敬语叠床（させていただきます）、常体（〜かも） |
| ko | 叙述用 -(스)ㅂ니다（없습니다），请求用 해 주세요，按钮用名词（삭제、취소） | 同一产品里 -세요 / -(으)십시오 混用、반말 |
| fr | vous，否定保留 ne | 行政腔（il convient de） |
| ru | вы（句中小写），简单动词 | 公文腔（при осуществлении） |
| ar | 现代标准语短句 | 方言、古典长句 |
| id | Anda，短祈使；Anda dapat 留着 | 公文字（mohon kesediaan） |
| hi | 日常的 आप，界面通行借词留着（ऐप、कैमरा） | 纯书面梵语 |
| tr | 直白礼貌体（Silinemez） | 公文后缀（gerçekleştirilememektedir） |
| de | du，动词句 | 名词化起句（Bei Aktivierung → Wenn du das einschaltest） |
| es | tú | 同一产品里 tú / usted 混用 |
| it | tu | 同一产品里 tu / Lei 混用 |
| pt-BR | você | o senhor 这类过度敬称 |
| th | 省人称 | ท่าน、句句加 ครับ / ค่ะ |
| vi | 无代词祈使 | 用 bạn có thể、quý khách 垫长 |

按钮用该语言界面惯用的动词形态，不用对用户的敬语命令：

| 语言 | 按钮形态 | 例 |
|---|---|---|
| de、fr、es、pt-BR、ru | 不定式 | Löschen、Supprimer、Eliminar、Apagar、Удалить |
| it | 第二人称单数命令式 | Elimina、Annulla |
| ja | 名词或短名 | 削除、キャンセル；不写「削除してください」 |
| ko | 名词 | 삭제、취소；해 주세요只用在说明句 |

性别未知时，形容词、分词不默认阳性（connecté、connesso、conectado），改用不带性别的句式（名词、不定式、换主语）。随名词变的词跟名词性数一致（invariati / invariate）。

### 简体中文

| 不要 | 要 |
|---|---|
| 这个文件删不掉 | 无法删除该文件 |
| 要删除吗？ | 确认删除该文件？ |
| 好的 | iOS「好」，Android、Web「确定」（各跟系统对话框） |
| 用过 N 次、使用 N 次 | 已使用 N 次；标签式写「使用次数」+ 数值 |
| 第 1/共 2 件 | 第 1 件（共 2 件） |
| 先去…再删 | 请先… |
| 匹配 100% | 匹配度 100% |

计数和进度不要把两种句式拼在一起。名词要完整。短语不要悬着不成句。「即可」是书面短句，留着。

### 繁体中文

不沿用简体公文词：

| 不要 | 要 |
|---|---|
| 作指示词的「該」（該檔案） | 此；「應該」等词里的「該」不动 |
| 屆時 | 到時 |
| 所限 | 把限制说完 |

简体用词不直接转繁体：

| 简体 | 繁体（台湾） |
|---|---|
| 文件（电脑文件） | 檔案 |
| 视频 | 影片 |
| 软件 | 軟體 |
| 默认 | 預設 |
| 网络 | 網路 |
| 信息（资料） | 資訊 |
| 信息、消息（message） | 訊息 |
| 质量 | 品質 |

### 英文

| 情形 | 写法 |
|---|---|
| 常见缩约 | 用，例如 can't、don't、isn't、aren't、doesn't、didn't、it's、that's、there's、you're、won't、you'll、couldn't |
| 不常见的缩约 | 不用：could've、it'll |
| 加重的警告 | 不缩：cannot、do not、it is |
| 法务正文 | 不缩 |
| you have | 缩约后仍是英语才收成 you've；You've more 不成立 |
| 名词 + 动词 | 不缩在名词上：the computer's not → the computer isn't；所有格 's 不受限 |
| 宾语 it + is | 不缩成 it's：The best way to find it is to ask them. |

缩约只替换原来那一个词，大小写跟着那个词：Title Case 元素里写 Couldn't、Don't，不把整句改小写。

### 其它语言的易错点

各语言按选定的敬称档位全文统一，不混用。

| 语言 | 规则 |
|---|---|
| de | 改成 du 时按格换：主格 Sie → du，宾格 Sie → dich，与格 Ihnen → dir，物主 Ihr- → dein-（带词尾：Ihre → deine，Ihren → deinen）；小写 sie 是「她」或「他们」，不要改 |
| it | 选 tu 时，小写 lei 是「她」，不要改；选 Lei 时敬称首字母大写 |
| it | 条件写成完整条件句（Se inserisci di nuovo lo stesso nome, viene ricreato），不用副动词句 |
| th | 短的「做不到」用「动词 + ไม่ได้」（ลบไม่ได้），不用 ไม่สามารถ…ได้；因果句里也可以这么收。ไม่ได้ 放在动词前是「没做」（ไม่ได้ลบ），不要放反 |
| th | 会形成叠字否定时（…ที่ไม่ได้ใช้ไม่ได้）保持 ไม่สามารถ…ได้；正面的 สามารถ 留着 |
| vi | 已经表示 you can 的 bạn có thể 不是垫长，留着 |
| ko | 已经是 -습니다 的叙述句不要成批改成해요체 |
| ko | 按韩文分写规则留空格（할 수 없습니다，不是 할수없습니다） |
| ko | 助词接占位符时写两种形态：을(를)、은(는)、이(가)、과(와)、(으)로 |
| ru | 能力或规则上做不到用 нельзя + 不定式；这一次没做成用 Не удалось…（Не удалось удалить） |
| tr | 大小写按 tr-TR 转换：i ↔ İ，ı ↔ I；不用默认的 Unicode 大小写转换，打字确认的全大写同样适用 |
| id | 介词 di、ke 与名词分写（di rumah），作前缀时连写（dihapus） |

「不受影响」用这种语言里「这些东西还在」的说法：

| 语言 | 写 | 不写 |
|---|---|---|
| en | stay the same、are kept | unaffected |
| de | bleiben unverändert | sind nicht betroffen |
| it | restano invariati | non sono interessati |

### 不要搬源语言的句架

中文源文案「确认删除该文件？」里的「确认」是中文句式，别的语言标题直接用动作问句：

| 语言 | 写法 |
|---|---|
| en | Delete This File?（iOS）、Delete this file?（Android、Web） |
| de | Diese Datei löschen? |
| it | Eliminare questo file? |

### 语法上必须的缩合

这些不是要拆开的缩略：

| 语言 | 留着 |
|---|---|
| fr | du、des、au、aux |
| pt-BR | do、da、dos、das、no、na、nos、nas、ao、à、pelo、pela |
| it | del、al、dal、nel、sul、della、nella 等介词 + 冠词整套 |
| de | am、im、beim、vom、zum、zur、ans、ins |
| es | del、al；代词 él 不缩（de él、a él） |

## 不按界面语体改的文字

| 对象 | 怎么处理 |
|---|---|
| 语音助手触发短语（Siri / 快捷指令 / Google Assistant） | 用户照着说出口，有意用口语，整体豁免 |
| 法务正文 | 不缩约，不按界面短句改写 |
| 营销与官网宣传 | 另一套语体；与界面共用的段落仍按界面语体写 |

## 句子怎么写

### 输入框占位符

- 只写示例，格式见下表。不重复字段名，不写选填、optional——字段名由标签承担。

  | 语言 | 格式 |
  |---|---|
  | zh | 如：X |
  | ja | 例：X |
  | en | 直接放例子，不加 e.g. 等前缀：name@example.com |

- 示例要具体到真实可用；跨字段示例语义自洽（名称是充电器，关键词就是电源适配器，不是另一件东西）。
- 搜索框不对应要填的字段，不套示例写法；写成引导提问（找什么？ / What are you looking for?）时，称呼按该语言语体（de Was suchst du?）。

### 指代与范围

- 页面已经限定的对象不再重复：进了某个团队空间的页面说「所有成员」就够，不再写「团队空间全体成员」。产品文档为说清归属写的全称，照抄进界面会啰嗦。
- 同一句能覆盖多种情形时用同一句（「此项目」而不是分开写「你的项目 / 团队的项目」）；只在「这一下会影响别人」且画面别处没交代时才分开写。
- 对象性质的说明（「对所有成员可见」这类）不挂在开关、清除等动作的说明里。进这一页的每条路径都经过一个能带说明的入口行时挂在入口行上，否则挂在页内。
- 一句话里并列多个系统权限名时，引号要么都给，要么都不给；只提一项不加引号。
- 界面名、权限名入句时用该语言的引号：

  | 语言 | 引号 |
  |---|---|
  | zh-Hans | “” |
  | zh-Hant、ja | 「」 |
  | en | “” |
  | fr | « »，内侧加窄不换行空格 |
  | de | „“ |
  | ru | «» |
  | es、it、pt-BR | 按项目约定，默认 “” |

### 破坏性操作

清除、删除、移除、丢弃各有所指，同一操作在各端、各处用同一个词。

- 按钮下的说明只写按钮名交代不了的范围或后果；按钮名已说完的不挂说明。只写这次操作直接相关的后果，不顺带讲别的机制。
- 说明按要交代的内容选句式。后果里不重复动作本身（「清除后，将删除…」是病句）。

  | 交代 | 句式 |
  |---|---|
  | 后果 | <动作>后，<后果>。<哪些东西>均不受影响。 |
  | 范围 | 仅<动作>… |

- 「不受影响」逐项列出具体的东西，不用会被误读的笼统词。
- 不写「无法恢复」，除非这个 App 里确实有能恢复的删除需要区分。

确认框：

| 部位 | 写法 |
|---|---|
| 标题 | 中文写「确认<动作><对象>？」，其它语言写该语言的动作问句。动作用触发按钮上的那个词，不换同义词；有数量或名字就带上 |
| 正文，触发按钮下已有说明 | 不写，不复述那句说明 |
| 正文，触发处没有说明（左滑、开关、菜单项） | 写范围或后果；没有要交代的就不写 |
| 正文要说哪些东西不受影响时 | 先说删掉的是什么，不直接从「<X>不受影响」起句 |
| 确认按钮 | 与触发按钮同名；由开关触发的写明连带后果：「关闭并清除」。不用「是 / 否」 |
| 默认按钮 | 破坏性按钮不设为默认，不能按回车直接触发 |

### 开关下的说明

说明随开关状态切换，不用一句话同时交代开与关：

| 开关状态 | 说明写什么 |
|---|---|
| 关着 | 打开之后会怎样 |
| 开着 | 此刻正在发生什么 |

关掉的破坏性后果不写进说明，由关闭确认讲。

### 空状态标题

片语式空状态标题不带句末标点，不限语言：No Activity Yet；中日文同样不加「。」。

## 进行态

管的是「用户刚触发的那一次动作还在跑」。

- 中文写成「…中」或「正在…」；其它语言用该语言的进行式或状态名词，不直译「中」。各语言都带省略号，用单字符 `…`（U+2026），不是三个点：

  | 语言 | 形式 | 例 |
  |---|---|---|
  | zh | 动词 + 中，或 正在 + 动词 | 同步中…、正在新建项目… |
  | ja | 动词 + 中 | 同期中… |
  | en | 现在分词 | Syncing… |
  | de | 被动进行式 | Wird synchronisiert… |

- 写正在发生的事，不是按钮原名：

  | 按钮 | 进行态 |
  |---|---|
  | 新建项目 | 正在新建项目… |
  | 转为共享 | 转换中… |

- 同一组按钮各给各的，不共用一句笼统的「处理中…」。
- 状态横幅标题带省略号；配确定进度计数的标题说的是「这件事是什么」，不加。
- 按钮进行中必须仍有可见文字，不能整个换成裸转圈；纯图标按钮才把图标换成转圈。

## 报错

- 始终显示一句本地化的、用户听得懂的文案。异常自身的文字（`message`、`localizedDescription` 等）不许顶替。
- 认得出原因的失败各有各的文案；认不出的给通用句。通用句带「请重试」，所以屏上没有重试入口的整屏失败要另给一句不劝重试的。
- 弹框标题说清「什么没做成」，一个动作一句，不用笼统的「操作失败」。动作词取本端对应按钮的既有译名。
- en 失败标题：试过但没做成用 Couldn't；规则上不允许用 Can't。大小写按平台：

  | 平台 | 例 |
  |---|---|
  | iOS | Couldn't Clear History |
  | Android、Web | Couldn't clear history |

- 正文写具体原因。按钮按情形取：

  | 情形 | 按钮 |
  |---|---|
  | 只有原因 | 一枚确认按钮，用系统对话框的叫法（zh-Hans：iOS「好」，Android、Web「确定」） |
  | 原因带着用户点一下就能解决的出路 | 「出路 + 取消」，出路是默认动作 |

- 加载失败不许借空状态表达（「暂无记录」或读数 0）。换成错误形态：警告图标 +「加载失败」+ 原因 +「重试」。

## 括号与空格

- 中日文默认用全角括号（），外侧不加空格：第 3 件（共 5 件）、按年（省 20%）。
- 项目改用半角括号时整套半角，不与全角混用。外侧空格按语言分：

  | 语言 | 外侧挨汉字 | 外侧挨西文、数字或占位符 |
  |---|---|---|
  | zh-Hans | 不空格：联系人(%ld) | 留一个半角空格：Microsoft Excel (XLSX) |
  | zh-Hant | 留一个半角空格：聯絡人 (%ld) | 留一个半角空格 |
  | ja | 不给半角规则，用全角 | —— |

- 其它语言用半角 `()`，外侧与相邻文字留一个半角空格，内侧不留。
- 外侧紧挨句首、句末、各语言的句读标点（。，、以及 , . ; : ? !），或本来已有空格时不补。
- 韩文助词紧贴括号：AI 스위치 (%1$s)를；“%1$s”을(를)。
- 代码里拼接的半角括号同样适用，空格写进字面量（`" ("`）。
- 各语言自己的标点：

  | 语言 | 规则 |
  |---|---|
  | fr | : ; ! ? 与 % 前加窄不换行空格（U+202F）；大写字母保留重音（Échec） |
  | es | 问句、叹句配开头的 ¿ ¡ |
  | ar | 问号 ؟、逗号 ،；括号照常写 ()，交给双向算法镜像，不手写反向括号 |

- 日文里 ASCII 词与假名、汉字之间默认不加空格：Apple IDを作成、アカウントID。项目采用加半角空格的风格（ID を表示、テナント ID）时全文统一，不混用。

## 大小写

有大小写的语言，大小写按这段文字在界面里的**角色**判，不按译文语法判。

### Android

全部句首大写（sentence case），跟 Material。不分元素名还是完整句。

### Web

默认句首大写，同 Android。项目的设计系统对大小写另有规定时从它。

### iOS

依据 Apple Style Guide 的 title-style capitalization，取词以 Apple 自家 iOS 该语言的本地化为准。

| 角色 | 大小写 |
|---|---|
| 界面元素名：导航标题、按钮、菜单项、分段控件、Tab、列表行与开关标签（片语时）、分组标题、App Intent 标题 | Title Case |
| 标题位（弹窗、横幅、空状态、sheet、upsell）不带句末标点的片段或短句 | Title Case（iCloud Storage Is Full） |
| 片段式问句 | Title Case（Delete Note?） |
| 带句末标点的完整句标题（含多句），以及完整问句（Are you sure you want to…?） | 句首大写；确认标题优先写成片段式问句 |
| 按钮进行态、片语式横幅标题、徽标、标签、读数值与状态值 | Title Case（Loading Plans…、Not Connected） |
| 完整句：说明、正文、页脚、占位符、读屏标签，以及本身是完整句的列表行与开关标签 | 句首大写 |
| 拼进某句话里的片段、复数与替换分支 | 跟随所在那句 |

Title Case 按语言取词：

| 语言 | 小写 | 容易误判、实际大写 | 首尾词 |
|---|---|---|---|
| en | 冠词、并列连词（and、but、or、nor），四个字母以内的介词（to、at、by、for、in、of、off、on、out、up、via、from、into、onto、over、with、per）及 as | 五个字母以上的介词（About、Between、Through）、从属连词（If、When、Because）、动词短语的小品词（Turn Off、Sign In） | 大写 |
| id | dan、atau、di、ke、dari、untuk、yang、dengan、dalam、pada、secara、hingga、sampai、tentang、per、oleh | tanpa、antara | 大写 |
| pt-BR | a、o、os、as、de、da、do、das、dos、e、em、no、na、nos、nas、ou、para、com、ao、à、um、uma、por、pelo、pela、pelos、pelas、até、sem、sobre、que，以及 desta / nesta / deste / neste 类缩合 | entre、contra、após | 大写 |
| tr | 只有 ve、ile、veya、yahut，以及分写的附着词与疑问小品词 de、da、ki、ya（含 ya da）、mı、mi、mu、mü；连写的 -de、-da、-ki 是词的一部分，不拆 | 其余后置词：için、kadar、gibi | 分写的附着词与疑问小品词在首尾也小写 |

- de、fr、es、it、vi、ru 等其余有大小写的语言：跟 Apple 一样用句首大写，不套 Title Case。
- 表外的词一律大写。id、pt-BR 的介词在 Apple 本地化里找不到样本时按小写；tr 不做这种类推，只认上表清单（TDK Yazım Kılavuzu「Büyük harflerin kullanıldığı yerler」）。
- en 连字符复合词第二段大写（Add-On、Follow-Up、%lld-Day），Built-in、Plug-in 除外；id、pt-BR 两段各自判断。

### 通用

- 括号里的内容按它自己在界面里的角色判，不因为进了括号就变。
- 打字确认要求用户输入的词：有大小写的语言写全大写；没有大小写的语言不受影响。
- 这些不随规则变动：

  | 类别 | 例 |
  |---|---|
  | 品牌与缩写 | iCloud、AI、API、URL |
  | 方案名 | —— |
  | 系统权限与系统屏幕的官方译名，照系统原文 | Motion & Fitness、Settings |
  | 默认数据名、法律文件名 | —— |
  | 语法要求的大写 | 德语名词、印尼语 Anda |

- 不要把 Title Case 和 sentence case 整段互转；iOS 的词首大写不原样搬进 Android 与 Web。

## 术语

- 同一事物全 App 只用一个词，按钮、标题、报错、履历里用同一个。改叫法时按「同一页面 + 同一概念」把键找全；中文常用量词省掉名词（「N 条」），要到 en 等语言里再搜一遍。
- 页面上同时出现多个可能被同一简称指代的东西时，写全称；只围绕一种对象的页面才用简称。
- 两个容易混淆的概念（如存储空间上限和月度额度），每种语言都给两个互不相同的词，一侧不借用另一侧的词。
- 界面不出现实现层术语（token、数据库名等），用用户可理解的单位与名称。
- 本 App 的名字用占位符从单一事实源取，不在文案里写字面量。

## 多端

- 同一功能各端（iOS、Android、Web）用同一套措辞、同一份译文，分组标题、说明句同样有无；只有某端不支持的功能才各说各的。平台专有叫法（系统「设置」等）按各平台惯例。
- 以一端为源同步到另一端时，先核对句中事实在目标端成不成立（权限项、功能是否存在），源端自身的语法错先在源端改掉。
- 句子里点到本端某个控件时用本端那个控件的既有译名。对齐的是说法和粒度，不要求两端逐字相同。
- 占位符语法可以不同，其余措辞相同。一句有两个及以上占位符时必须带序号（iOS `%1$@`、`%2$lld`），译文才能调换语序：

  | 平台 | 字符串 | 整数 |
  |---|---|---|
  | iOS | `%@` | `%lld` |
  | Android | `%1$s` | `%1$d` |
  | Web（ICU MessageFormat） | `{name}` | `{count, number}`；复数用 `{count, plural, …}` |

- 复数按 CLDR 类别给全（ar 有 zero、one、two、few、many、other，ru 有 one、few、many、other），不只给 one / other；不在占位符后手拼英文复数 s。
- Android 字符串的撇号写 `\'`、双引号写 `\"`，这是 aapt 资源转义，不是 XML 转义；多写一层反斜杠界面上就会看见反斜杠。
- 官网、法务页提到 App 界面上的名字时逐语言照抄 App 里的实际译文；App 里改了名字要回头同步。
