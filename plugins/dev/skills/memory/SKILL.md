# 开发记忆

开发记忆存放在 `@docs/dev-memory/`，记录项目特有的、容易被忽略的经验与约定。本 skill 有**读取**和**沉淀**两种用法。

补充说明（可选）：

<task>
$ARGUMENTS
</task>

## 判断用哪种

- 任务尚未开始、想了解项目注意事项 → **读取记忆**
- 开发已完成、要回顾沉淀经验 → **沉淀记忆**
- 无法从语境判断时，默认**读取记忆**

---

## 读取记忆

1. **阅读索引**：先读 `@docs/dev-memory/README.md`，了解记忆的整体结构
2. **定位相关记忆**：根据当前任务类型，从索引中找到相关的记忆文档
3. **阅读相关记忆**：仔细阅读与当前任务相关的记忆内容
4. **应用到开发中**：在后续开发中主动遵循记忆中的注意事项

注意：

- 记忆是从历次开发中积累的经验教训，优先级高于一般性假设
- 如果记忆中的内容与你的默认行为冲突，应遵循记忆中的要求
- 记忆会随项目演进不断更新，每次开发前都应检查相关记忆

---

## 沉淀记忆

回顾本次开发过程，判断是否有值得沉淀的经验。如有，归纳整理到 `@docs/dev-memory/`；如无，直接告知用户「本次无需记录」即可。

> ⚠️ **这是可选任务**：并非每次开发都有值得记录的内容。不要强行总结，没有就是没有。

### 判断标准

记忆的读者是**后来的维护者**（包括未来的你和其它 agent）。写之前先问一句：这条能让他更快建立上下文、少踩一次坑吗？不能就不写。

**应该记录**：

- 项目特有的约定或规范（不同于通用做法）
- 与直觉相反、不提前说明就会写错的实现方式
- 容易被忽略但很重要的细节
- 被明确指正过、或反复犯过的同类错误

**不应该记录**：

- 代码变迁历史——改过什么、以前怎么写的、为什么换掉旧方案
- 已经过时、与当前代码不符的内容（发现了就地改掉或删掉，不要与新内容并列保留）
- 通用编程知识（基础语法、框架常识）
- 已在 CLAUDE.md 或 Skill 中写明的规范
- 一次性的、不会再遇到的问题

**保持精简**：记忆会被整份读进上下文，每一条都在占预算。一条通常一两行，只写结论；背景、推导过程、代码示例只在没有它就看不懂时才写。

### 执行步骤

1. **回顾开发过程**：梳理本次对话中遇到的问题，特别是被用户指正的地方
2. **筛选有价值的内容**：判断问题是否具有复用价值，是否值得记录
3. **阅读现有记忆**：查看 `@docs/dev-memory/README.md` 了解现有记忆结构
4. **智能归类**：
   - 如果问题属于已有分类 → 添加到对应文档
   - 如果问题是新类型 → 根据需要创建新文档或新分类
   - 如果已有记忆被本次改动推翻 → 就地改写或删除，不要追加"原来是…现在是…"
5. **更新索引**：如果创建了新文档，在 README.md 中添加索引链接

### 记忆组织原则

#### 目录结构演进

记忆目录采用**渐进式组织**，随内容增长自然演进：

```
# 初期（问题较少）
docs/dev-memory/
├── README.md           # 索引 + 少量记忆
└── common-issues.md    # 通用问题汇总

# 中期（问题增多，开始分类）
docs/dev-memory/
├── README.md
├── components/         # 组件相关
│   └── props-and-slots.md
├── api/                # API 相关
│   └── validation.md
└── i18n.md            # 国际化相关

# 后期（形成完整体系）
docs/dev-memory/
├── README.md
├── components/
│   ├── README.md
│   ├── props-and-slots.md
│   └── lifecycle.md
├── api/
│   ├── README.md
│   └── ...
└── ...
```

#### 分类时机

- 单个文件超过 **15 条**相关记忆时，考虑拆分
- 同一主题的记忆超过 **5 条**时，考虑独立成文件
- 不要过早创建空目录或占位文件

#### 记忆格式

记忆是**直接可用的规则**，不是问题回顾。不需要描述"犯了什么错"，只需要告诉未来的自己"应该怎么做"。

```markdown
### 规则标题

- 规则要点 1
- 规则要点 2
```

**反面示例**（不要这样写）：
```markdown
### 不要维护重复的数据映射
**问题**：创建了 LANGUAGE_NAMES 映射，而 locales.ts 中已有...  ← 冗余，不需要
**正确做法**：使用 getLocaleNameByCode()...
```

**正面示例**（应该这样写）：
```markdown
### 语言名称获取
- 使用 `getLocaleNameByCode(code)` 从 locales.ts 获取，不要创建单独的映射表
```
