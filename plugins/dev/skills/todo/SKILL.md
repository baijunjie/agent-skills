# 检查 TODO

只检查、只汇报，**不要动代码**（不删标记、不实现、不改写），列完停下等用户指示。拿不准就汇报。

## 扫哪些

源码与项目文档里的 `TODO` / `FIXME` / `HACK` / `XXX` 标记；尚未勾选的计划条目不算。

## 怎么判定

**逐条查证，不要只读标记文本就下结论**：看它所在的代码现在什么样、它提到的对象（接口、开关、版本、前置工作）还在不在。

| 分类 | 判据 |
|---|---|
| **已过时** | 标记要求的事已不用再做：要做的事已经做了、提到的对象已删除、描述的问题已不复现 |
| **可以处理** | 前提成立且阻塞已解除：依赖已就位、外部条件已满足、前置工作已完成 |
| **还不能处理** | 阻塞仍在，且能指名卡在什么上 |
| **无法判定** | 查不出前提现状、标记没写清要做什么，或同时命中多类且分不出主次 |

- 说不出依据的归「无法判定」，不要硬塞进前三类。
- 还有没做完的部分（含条件已满足、但要求的删代码、换实现还没做）就不归「已过时」，按没做完的部分归类。
- **找不到标记点名的计划文档不等于前提消失**（计划文档做完常被删掉）：回代码确认它所指的临时实现是否仍在被使用。

## 怎么列

按 已过时 → 可以处理 → 还不能处理 → 无法判定 分组，一条一行：位置 `文件:行号`、标记原文摘要、**判定依据**（查到了什么才这么判，不要省成一个分类词）。

列完先问用户**是否清理掉已过时的标记**，答完再问**是否开始处理「可以处理」的条目、处理哪几条**。
