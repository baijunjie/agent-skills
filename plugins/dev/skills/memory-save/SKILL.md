# 保存开发记忆

## 任务目标

回顾本次开发过程，判断是否有值得沉淀的经验。如有，归纳整理到 `@docs/dev-memory/` 目录下；如无，直接告知用户「本次无需记录」即可。

> ⚠️ **这是可选任务**：并非每次开发都有值得记录的内容。不要强行总结，没有就是没有。

## 什么内容应该被记录

- 被用户/开发者明确指出的错误或遗漏
- 多次犯过的同类错误
- 项目特有的约定或规范（不同于通用做法）
- 容易被忽略但很重要的细节
- 与直觉相反的实现方式

## 什么内容不应该被记录

- 通用的编程知识（如基础语法）
- 已在 CLAUDE.md 或 Skill 中明确说明的规范
- 一次性的、不具有复用价值的问题

## 执行步骤

1. **回顾开发过程**：梳理本次对话中遇到的问题，特别是被用户指正的地方
2. **筛选有价值的内容**：判断问题是否具有复用价值，是否值得记录
3. **阅读现有记忆**：查看 `@docs/dev-memory/README.md` 了解现有记忆结构
4. **智能归类**：
   - 如果问题属于已有分类 → 添加到对应文档
   - 如果问题是新类型 → 根据需要创建新文档或新分类
5. **更新索引**：如果创建了新文档，在 README.md 中添加索引链接

## 记忆组织原则

### 目录结构演进

记忆目录采用**渐进式组织**，随内容增长自然演进：

```
# 初期（问题较少）
docs/dev-memory/
├── README.md           # 索引 + 少量记忆
└── common-issues.md    # 通用问题汇总

# 中期（问题增多，开始分类）
docs/dev-memory/
├── README.md
├── components/         # 组件相关
│   └── props-and-slots.md
├── api/                # API 相关
│   └── validation.md
└── i18n.md            # 国际化相关

# 后期（形成完整体系）
docs/dev-memory/
├── README.md
├── components/
│   ├── README.md
│   ├── props-and-slots.md
│   └── lifecycle.md
├── api/
│   ├── README.md
│   └── ...
└── ...
```

### 分类时机

- 单个文件超过 **15 条**相关记忆时，考虑拆分
- 同一主题的记忆超过 **5 条**时，考虑独立成文件
- 不要过早创建空目录或占位文件

### 记忆格式

记忆是**直接可用的规则**，不是问题回顾。不需要描述"犯了什么错"，只需要告诉未来的自己"应该怎么做"。

```markdown
### 规则标题

- 规则要点 1
- 规则要点 2
```

**反面示例**（不要这样写）：
```markdown
### 不要维护重复的数据映射
**问题**：创建了 LANGUAGE_NAMES 映射，而 locales.ts 中已有...  ← 冗余，不需要
**正确做法**：使用 getLocaleNameByCode()...
```

**正面示例**（应该这样写）：
```markdown
### 语言名称获取
- 使用 `getLocaleNameByCode(code)` 从 locales.ts 获取，不要创建单独的映射表
```
