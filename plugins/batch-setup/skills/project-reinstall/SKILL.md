# 重装项目级安装

本 skill 自己不写文件：找出当前项目里装过的安装器，读它们的 `SKILL.md` 照做，按最新模板重装。
那些安装器禁止模型调用，只能读文件照做；除第 5 步列明的几处外，都照它们自己的 `SKILL.md` 做。

1. **确认在 git 仓库里**：不是就汇报，不装任何东西。
2. **找到安装器**：取 `setup-agent`、`setup-git`、`setup-tools`、`setup-knowledge` 各自最新版本的目录；找不到的 plugin 跳过并告知用户，不要自己安装 plugin；报出非版本号目录的，由用户确认用哪个目录：

   ```bash
   ROOT="${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT:-${SKILL_DIR:?先将 SKILL_DIR 设为当前 SKILL.md 的绝对父目录}/../..}}"
   bash "$ROOT/scripts/latest-plugins.sh" setup-agent setup-git setup-tools setup-knowledge
   ```

   安装器是这些目录下的 `skills/<skill>/SKILL.md`。
3. **查装过哪些**：逐个读带项目级安装节的安装器，看它在项目里会为每个宿主写出什么，查这些产物在不在。
   - 认出任一只有它会写出的产物（如指令文件里它的那对 `<!-- setup-…:begin|end -->` 标记、它装的 skill 或子代理），就算它装过，缺的产物在清单里注明、重装会补回；几个安装器共用的产物不作依据。没装过的不新装，在清单里列为「未发现安装」，只有共用产物的注明判定不了。
   - 装在哪个宿主以产物所在的宿主路径为准；产物不分宿主或经软链两边共享、分不出的，交给用户指定宿主。
   - 看着是 `setup-*` 装出、却对不上任何现有安装器的（如没有安装器认领的 `setup-…` 标记、像是旧版装出而现有安装器都不装的 skill 或子代理），列进清单的「认不出归属」，不动它。
4. **先确认清单**：写入任何文件之前，把「宿主 × 安装器」的清单交给用户定，连同每个 plugin 用的版本与目录（脚本只看运行本 skill 的宿主的缓存，两个宿主的格都用这份模板；能查到另一宿主已装的版本就并列）；用户确认后再开始。
5. **逐格重装**：清单里每一格（一个宿主上的一个安装器）当作一次独立安装，`setup-agent:workflow` 的各格放在其它所有格之后（它按已装的 skill 编排工作流）。每一格按该安装器整份 `SKILL.md` 执行，作用域固定为项目级、不再问作用域；宿主按这一格走，安装器里说的「当前宿主」就是这一格的宿主。同时遵守：
   - 执行安装器的任何 shell，每次都先 `unset PLUGIN_ROOT CLAUDE_PLUGIN_ROOT`，并把 `SKILL_DIR` 设为**该安装器 `SKILL.md` 的绝对父目录**（`<plugin 目录>/skills/<skill>`）：`PLUGIN_ROOT`、`CLAUDE_PLUGIN_ROOT` 此时指向本 plugin，不清掉会去本 plugin 里找模板。
   - 它停下来问用户的，原样转给用户，等用户决定后再继续。
   - 命令报错时，安装器自己规定了处理（问用户、恢复）的照它做，走完仍装不成才算失败。
   - 它说的「结束」「汇报并停下」只管这一格：这一格还没写入任何文件时，它因用户不装或失败而结束的，记下原因，继续下一格。
   - 这一格已写入部分后失败或被用户放弃，或用户叫停整次运行的，停下汇报已写入了什么，由用户决定恢复、重试还是保留，以及剩下的格还做不做。
6. **汇总**：在最终回复里按宿主逐个写清重装成的、没重装成的（附原因）与「认不出归属」的，并把各安装器要用户自己动手的事项集中列出，提醒用户改动要提交进版本库才随仓库生效、重装的内容要在新会话里才生效。

拿不准就汇报。
