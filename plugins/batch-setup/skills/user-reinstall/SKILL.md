# 重装用户级安装

本 skill 自己不写文件：找出用户级配置里装过的安装器，读它们的 `SKILL.md` 照做，按最新模板重装。
那些安装器禁止模型调用，只能读文件照做；除本 skill 各步明确规定的几处外，都照它们自己的 `SKILL.md` 做。

1. **找到安装器**：取 `setup-agent`、`setup-git`、`setup-tools`、`setup-knowledge` 各自最新版本的目录；找不到的 plugin 跳过并告知用户，不要自己安装 plugin：

   ```bash
   ROOT="${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT:-${SKILL_DIR:?先将 SKILL_DIR 设为当前 SKILL.md 的绝对父目录}/../..}}"
   bash "$ROOT/scripts/latest-plugins.sh" setup-agent setup-git setup-tools setup-knowledge
   ```

   安装器是这些目录下的 `skills/<skill>/SKILL.md`。
2. **查装过哪些**：列出这些 plugin 下的全部 skill，逐个读到用户级安装节所在处，不凭名字跳过；带用户级安装节的安装器，看它在用户级会为每个宿主写出什么，查这些产物在不在，清单里写明读过的安装器。
   - 认出任一只有它会写出的产物（如指令文件里它的那对 `<!-- setup-…:begin|end -->` 标记、它装的 skill、子代理、输出风格文件），就算它装过，几个安装器共用的产物不作依据。没装过的不新装、不进清单；只有共用产物、归属待定的，在清单里单列「归属待定」，请用户在这一次确认里指定按哪个安装器重装；指定的并入清单、照下一条判定要不要更新，不另起确认。
   - 装在哪个宿主以产物所在的宿主路径为准；经软链两边共享、分不出宿主的，汇报并等用户指定。
   - **判定要不要更新**：对每个装过的格，只读地拿最新模板与用户级现有产物比：按该安装器的安装步骤，推出它会写出的每个文件，与现有文件比对（只往配置文件里设某个键的，比对那个键的值）；「本安装器的定制值」所列位置的差异不算，缺文件算有差异。只有全部一致才判「无需更新」，其余（有差异、判不了、拿不准）一律判「需更新」，注明差异文件或原因。
   - 看着是 `setup-*` 装出、却对不上任何现有安装器的（如没有安装器认领的 `setup-…` 标记、像是旧版装出而现有安装器都不装的 skill 或子代理），列进清单的「认不出归属」，不动它；属于上面找不到的 plugin 的，不算认不出归属，单列「plugin 未找到」，提示用户先装或更新该 plugin。
3. **确认一次清单**：写入任何文件之前，把用户级已装的「宿主 × 安装器」逐格列给用户，每格标「需更新」（附差异文件）或「无需更新」；没装过的不列，另外单列「归属待定」与「认不出归属」的。连同每个 plugin 用的版本与目录（脚本只看运行本 skill 的宿主的缓存，两个宿主的格都用这份模板；能查到另一宿主已装的版本就并列；两边版本不一致的在清单里显式提示，由用户定按这份模板继续，还是先去另一宿主更新 plugin 再来）、每个宿主查过的目录及其来源（环境变量或默认值，默认值请用户核对）。用户确认一次即开始：只重装「需更新」的格，「无需更新」的跳过。此前为定宿主、目录而先问的不计入这一次，目录被改后重扫、重列清单也不算多一次确认；清单确认后，未出问题的格不再问是否重装，出问题时按下面的停下规则处理。
4. **逐格重装**：清单里要重装的每一格（一个宿主上的一个安装器）当作一次独立安装。每一格按该安装器整份 `SKILL.md` 执行，作用域固定为用户级、不再问作用域，也不因当前目录不是 git 仓库而停下；宿主按这一格走，安装器里说的「当前宿主」就是这一格的宿主。同时遵守：
   - 执行安装器的任何 shell，每次都先 `unset PLUGIN_ROOT CLAUDE_PLUGIN_ROOT`，导出清单里确认的 `CLAUDE_CONFIG_DIR`、`CODEX_HOME`（安装器写死的路径照原样），并把 `SKILL_DIR` 设为**该安装器 `SKILL.md` 的绝对父目录**（`<plugin 目录>/skills/<skill>`）：`PLUGIN_ROOT`、`CLAUDE_PLUGIN_ROOT` 此时指向本 plugin，不清掉会去本 plugin 里找模板。
   - 它为冲突、手改、软链等具体决定停下来问用户的，原样转给用户，等用户决定后再继续；但它「是否安装」这类整格层面的确认，已由清单确认代替，不再问。
   - 它说的「结束」「汇报并停下」只管这一格：这一格还没写入任何文件时，它因用户不装或失败而结束的，记下原因，继续下一格。
   - 这一格已写入部分后失败或被用户放弃，或用户叫停整次运行的，停下汇报已写入了什么，由用户决定恢复、重试还是保留，以及剩下的格还做不做。
5. **汇总**：在最终回复里按宿主逐个写清重装成的、跳过的（无需更新）、没重装成的（附原因）与「认不出归属」的，并把各安装器要用户自己动手的事项集中列出，并告知用户重装的内容要在新会话里才生效。

本文没有另行规定的情形，拿不准就汇报。
