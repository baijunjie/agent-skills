## 本项目约定

{{include: project-conventions}}

填的框架已不在项目依赖里也算失效。本次改动就是换框架或改测试命令的：用改后的命令跑，在最终回复里提醒用户重新运行安装器更新「本项目约定」。

填写与重装时按项目现状核对，确定不了的沿用；monorepo 每个包在表里各填一行，表下两项各包不同时分别写明。

| 范围 | 框架 | 测试根目录 | 路径映射 | 共享辅助代码 | 运行全部 | 运行指定文件 | 按改动选测试 |
|---|---|---|---|---|---|---|---|
| <包的路径；不是 monorepo 写「整个项目」> | <框架名（项目现状；没有时由用户选定）> | <测试根目录（项目现状 → 语言或构建工具约定 → 默认 tests/unit/）；表下选 ③ 的写「无」> | <源路径模式> → <测试路径模式（项目已有测试的镜像方式 → 默认按相对项目（包）根的完整路径镜像，只有单一源码根时省掉这一级；表下选 ③ 的写与源文件同目录的模式）> | <共享辅助代码的位置（项目现状 → 默认测试根目录下的 helpers/；表下选 ③ 的默认源码根下的 test-helpers/）> | <运行全部测试的命令> | <运行指定测试文件的命令> | <框架自带的按改动选测试的命令；框架没有这种能力写「无」> |

- 已有与源码同目录的测试（按语言惯例放的除外）怎么处理：<安装时询问用户，三选一：① 旧测试留在原处，新测试进测试根目录（默认）② 旧测试随源文件被改逐个迁移到测试根目录 ③ 新旧测试都放源码同目录；项目里没有这类旧测试写「无」>
- 按语言惯例放测试的语言：<项目里按语言惯例放测试、不套测试根目录与镜像规则的语言及其惯例，如 Go（同目录 `_test.go`）、Rust（源文件内的 `#[cfg(test)]` 模块）；没有写「无」>

## 框架配置要求

框架是新装的还是项目已有的，配置都要满足：

- 收集「本项目约定」规定的测试位置；选 ①、② 时留在源码同目录的旧测试照样收集，其它位置不收集。允许不同目录下出现同名测试文件，镜像结构必然会有。
- 测试文件纳入类型检查与 Lint，排除在构建产物与发布包之外。

## 收尾：补测试

1. 列出本次改动的源文件，含新增、改名、删除。
2. **派 `test-writer` 子代理补测试，有子代理机制时不要自己写**（没有的见表后）：写代码的人按自己的实现写断言，测试只会给实现盖章。写法在它自己的定义里，你只交代改动清单、每处改动**应有的行为**和用户定下的取舍——它看不见你们的对话，没交代的预期只能照实现反推。只改了不可测的文件（判据见本节末）时不必派，自己按「运行范围」跑。
3. 按下表逐条处理它的报告。
4. 之后源码又改了（审查意见、修缺陷）就重跑受影响的测试；改出了新行为就再派它补。

| 报告里的 | 做法 |
|---|---|
| 失败用例指向本次改动的缺陷 | 你改源码，不要让它改断言迁就实现 |
| 失败用例指向本次范围以外的既有缺陷 | 按「测试发现源码缺陷时」处置 |
| 测试本身写错 | 它改 |
| 预期说不清、列为待定的 | 你按需求定，需求也定不了就交给用户定；定下来发现实现不符的，按「测试发现源码缺陷时」处置 |
| 难测、需改源码结构 | 你判断改不改，改动大就交给用户定 |
| 建议整批迁移旧测试 | 交给用户定 |

## 测试发现源码缺陷时

- 本次改动引入的缺陷，你改源码；本次范围以外的既有缺陷，交给用户定：本次修，还是先交接出去。
- 实现看着可疑、期望行为又拿不出判定依据的不算缺陷：不按猜的期望写进测试，交给用户定；给出口径的按口径写测试，实现不符才按缺陷走，定不了的按项目的需求流程先把预期定下来。

决定交接的，下面几条都要做到：

- **每个缺陷都要有按期望行为断言的复现用例**，只留文字清单不算交接。
{{include: unit-test-no-weakening}}
- 记录要能单独交接：项目有自己的缺陷记录方式就走它，没有就在最终回复里列出，由用户决定去处。要素是位置、现象、期望行为及其依据、复现用例的文件路径与用例名、怎么把它恢复成会跑的状态、修法建议（看得出来才写）；一个缺陷（或同根同源的一组）一份。
- 引用是单向的：记录指向测试，测试里不写记录的路径，记录删掉后那会成为死引用。
- 写不出可靠复现的（死代码、加载时就固化了）不硬写，在记录里写明为什么。
- 挂起复现用例优先沿用项目已用的方式，其次用框架修好后会反过来报错的「已知失败」标记（`it.fails`、strict 的 `xfail` 等），都没有就整体注释掉，上方留一行 `TODO` 写明原因、恢复条件与缺陷现象；恢复后、修复前必须是失败的。

修复缺陷的那次改动，同时恢复复现用例、清掉对应记录。
