# 安装项目级 LaunchAgent 定时任务安装器

装出的是跑在用户 GUI 会话里的 LaunchAgent：要登录态的命令行工具、headful 浏览器在 cron 下起不来
（cron 的进程不在 GUI 会话里，读不到 login keychain），这类任务才成立；代价是它跟着登录会话，注销或关机期间不跑。
当前机器不是 macOS（`uname -s` 不是 Darwin），或任务要在无人登录的机器上跑时，**汇报**，不装。

本安装器另外要查的冲突：

- 第 1 步定的位置之外另有一套 LaunchAgent 安装脚本（约定位置上的同名文件按「查冲突」算「装过」，不在此列）；或项目已在用别的定时机制（crontab 等，别的安装器装出的那套也算）：
  两套并存会让同一任务跑两遍，留哪一套**交给用户定**。本安装器只装 LaunchAgent 这一套，不去改机器上的 crontab（在仓库外、删了不可逆），要迁走的旧任务请用户自己卸。
- 第 6 步的统一入口里已有同名、命令不同的 `launchd:install` / `launchd:uninstall` / `launchd:status` 或对应 target。
- 指令文件标记范围之外已有定时任务怎么改的说明。

## 项目级安装

1. **定脚本位置**：仓库里已有本安装器装出的 `launchd/`（里面有模板的 `common.sh`、`install.sh`、`uninstall.sh`、`status.sh`、`tasks.conf` 中任何一个就算，缺的几个照重装补齐）就沿用它的位置，这次即重装；
   找到多份这样的目录时按「现状与预期不符时」处理。都没有就放进项目已有脚本目录（`scripts/`、`bin/`、`tools/` 等）下的 `launchd/`，没有脚本目录就用 `scripts/launchd/`。
2. **拷贝模板**：已装过的，先按「重装」读出定制值，再执行下面的命令，已有的同名文件整份覆盖。`D` 设为第 1 步定的脚本目录，相对项目根目录（如 `scripts`）：

   ```bash
   {{include: project-root}}
   : "${TEMPLATE_DIR:?}"
   D=<脚本目录>
   : "${D:?}"
   mkdir -p "$D/launchd"
   cp "$TEMPLATE_DIR/"* "$D/launchd/"
   chmod +x "$D/launchd/install.sh" "$D/launchd/uninstall.sh" "$D/launchd/status.sh"
   ```

3. **对齐项目**：直接改 `common.sh` 里下面三个变量的默认值：

   | 变量 | 记录什么 | 怎么定 | 模板默认值 |
   |------|----------|--------|------------|
   | `PROJECT_ROOT` | 项目根目录 | 由项目现状得出：脚本不在 `<项目根>/<一级目录>/launchd/` 这个深度时只改 `../..` 的层级，不写绝对路径（`common.sh` 随仓库提交）；判断不了时沿用第 2 步读出的旧值（首次安装用模板默认值） | `launchd/` 目录上溯两级 |
   | `LOG_DIR` | 任务输出的日志目录 | 由项目现状得出：项目已有约定的日志目录时用它；判断不了时沿用第 2 步读出的旧值（首次安装用模板默认值） | `<项目根>/logs/launchd` |
   | `LABEL_PREFIX` | LaunchAgent 标签前缀，也是认出哪些 plist 属于本项目的唯一依据，要求项目移动后不变、不与别的项目撞车 | 旧 `common.sh` 里还是模板默认值（首次安装看新拷贝的）、算出的又是 `local.p<数字>`（取自项目根路径的 cksum，项目一移动就变）时，问用户要一个固定前缀（用户提供），用户没意见就填这个 `local.p<数字>`；其余情形重装时旧值原样填回、首次安装保持模板默认值，用户要求时才填固定前缀 | 由项目根目录名算出；目录名含非 ASCII 字符或没有字母数字时取项目根路径的 cksum |

   先定好 `PROJECT_ROOT`（重装时 `LABEL_PREFIX` 先按第 2 步读出的旧值填回），再执行 `sh <脚本目录>/launchd/install.sh --dry-run`，按首行 `标签前缀: <前缀>` 与上表定好 `LOG_DIR`、`LABEL_PREFIX`，再跑一次确认不撞车；它随后打印的「项目目录」与真实项目根不一致时，`PROJECT_ROOT` 还没定对，先改它。
   `--dry-run` 报错说前缀被占用时（报错里给出占着它的项目根，或那个 plist 的路径），问用户：别的项目在用就要一个固定前缀，已弃用就请用户先在那个项目里卸掉它的 LaunchAgent 再装；
   占着前缀的是没有生成标记的 plist（用户手写的 LaunchAgent）时一律改前缀，不替用户删它。
   重装时在只读地列出的 `~/Library/LaunchAgents` 里找本项目已装的 plist：按 plist 开头 `<!-- generated by install.sh; project: <项目根> -->` 记的项目根认，记的是本项目现在或曾经的路径才算本项目的（项目搬家、改名后它们的标签还是旧前缀）。
   不按标签名猜：认不出就把这些标签与它们记的项目根列给用户，由用户认，认不出来的不卸。旧前缀与最终定下的不同时记下旧前缀，第 9 步要用。
4. **填任务清单**：任务只写在 `tasks.conf` 的界线行 `# ---- 本项目的任务写在这一行之后 ----` 之后。
   先按「重装」填回读出的旧内容，再加用户已有的其它定时需求；**不要凭空编任务**，没有明确任务就让界线行之后保持空白交付。新加的任务要满足：
   - 命令在项目根目录下能直接跑通，要先编译的指向编译产物；
   - 解释器由版本管理器按会话注入 PATH 的（fnm、nvm 的 shell 集成等），写解释器的绝对路径；
   - 日和星期不要同时限定（cron 按「或」算而 launchd 按「与」算，`install.sh` 会报错退出），要两种条件就拆成两条任务；
   - 可能跑得比调度间隔还久的，拉长间隔或让脚本自己加锁，免得重叠执行；
   - 密钥等敏感值走项目原有的 `.env` / 配置文件，不写进 `tasks.conf`（它随仓库提交）。
5. **忽略日志目录**：`.gitignore` 还没忽略日志目录的，加上。
6. **注册入口**（项目有统一入口时才做）：`package.json` 加 `"launchd:install"` / `"launchd:uninstall"` / `"launchd:status"`，
   或 `Makefile` 加对应 target，命令就是 `sh <脚本目录>/launchd/install.sh` / `uninstall.sh` / `status.sh`。
7. **挂说明**：Codex 在项目根目录的 `AGENTS.md`、Claude Code 在 `CLAUDE.md` 里写下面这段（没有就新建），`<脚本目录>` 换成第 1 步定的位置；
   任务格式和参数只留在 `tasks.conf` 的注释里，不复制到这里：

   ```markdown
   <!-- {{marker}}:begin -->

   定时任务改 `<脚本目录>/launchd/tasks.conf` 后执行 `sh <脚本目录>/launchd/install.sh` 生效，不要手改 `~/Library/LaunchAgents` 下的 plist；跑 `sh <脚本目录>/launchd/status.sh` 看现在装了什么、上次跑成什么样。

   <!-- {{marker}}:end -->
   ```
8. **不要替用户执行 `install.sh`**：它往用户账号的 `~/Library/LaunchAgents` 写 plist 并立刻加载，不是仓库内容；交付后告知用户自己跑，或明确征得同意再跑。
   `install.sh --dry-run` 只读，可以直接执行。
9. **告知用户**：
   - 装出的 `launchd/` 与这次改到的指令文件、`.gitignore`、`package.json` / `Makefile` 都要提交；指令文件里的说明 Codex 开启新会话后生效，Claude Code 如未生效就重启。
   - plist 每台机器、每个账号各一份：换机器或换用户、新版改了命令或路径、以及这次是重装的，都要重跑 `install.sh`；第 3 步记下了旧前缀的，先 `LAUNCHD_LABEL_PREFIX=<旧前缀> sh <脚本目录>/launchd/uninstall.sh` 再装，否则旧 plist 留在机器上、任务跑两遍也不报错；卸载报撞车时不要硬删，按第 3 步的撞车处理。
   - 任务要跑就得保持登录：注销与关机期间不跑，重新登录后自动加载；装在非 macOS 机器上跑不起来。
   - 以后的任务只写在 `tasks.conf` 的界线行之后：界线行之前的改动，重装时只保留已启用的任务行。

本安装器的定制值：

- `launchd/` 所在的脚本目录：第 1 步按已装的位置沿用。
- `common.sh` 里 `PROJECT_ROOT`、`LOG_DIR`、`LABEL_PREFIX` 的默认值：第 2 步读出，第 3 步按表重新确定或填回。
- `tasks.conf` 界线行之后的全部内容（任务行、被注释停用的任务、用户写的注释与空行），以及界线行之前已启用（不以 `#` 开头）的任务行：
  第 2 步读出，第 4 步原样填回到新模板的界线行之后，界线行之前的那些放在最前面。
